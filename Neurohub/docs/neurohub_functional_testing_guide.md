# NeuroHub Functional Testing Guide

**Module Purpose:** Centralized orchestrator for the NMTK suite. It translates specifications into configurations, manages neuromorphic project configurations, coordinates cross-module workflow Directed Acyclic Graphs (DAGs), tracks shared assets (e.g., NIR models), and ensures strict Contract-Driven Development (CDD) data compliance across the ecosystem.

---

### Core Functional Walkthrough (The "Happy Path")

This walkthrough verifies the primary orchestration and project management lifecycle within the NeuroHub interface.

1. **Project Creation via Wizard:**
   * **Action:** Click "New Project" to launch the Scaffold Wizard.
   * **Input:** Select a Neuromorphic Framework (e.g., *Norse* or *Lava*), a Hardware Target (e.g., *Intel Loihi 2* or *SpiNNaker*), a Task Type, and a base Neuron Model (e.g., *Leaky Integrate-and-Fire (LIF)*). Submit the form.
   * **Expected Output:** The UI transitions to the Project Dashboard. The new project is displayed with a "Draft" or "Active" status, and the configuration details match the wizard inputs.

2. **Workflow DAG Definition:**
   * **Action:** Navigate to the "Workflows" tab within the project and define a multi-step pipeline (e.g., Step 1: `Dataset Prep` -> Step 2: `SNN Training` -> Step 3: `NIR Export`).
   * **Input:** Draw connections (dependencies) between these steps in the UI.
   * **Expected Output:** The nodes visually connect. The UI successfully saves the pipeline without topological errors, generating a valid Directed Acyclic Graph.

3. **Shared Asset Registration:**
   * **Action:** Upload or link a simulated Neuromorphic Intermediate Representation (.nir) model file to the project's asset registry.
   * **Expected Output:** The asset appears in the list with an automatically generated SHA-256 integrity hash and a categorized asset type (`nir`).

4. **Activity Feed Monitoring:**
   * **Action:** Observe the `ActivityFeed` widget on the main dashboard.
   * **Expected Output:** You should see chronological, real-time events corresponding to your previous actions (e.g., "Project Created", "Workflow Updated", "Asset Registered").

### Data & State Validation

To verify that the underlying logic and mathematical/structural models are functioning correctly, perform the following validation checks:

* **DAG Topological Sort & Validation:** Inspect the JSON payload generated by saving the workflow (via browser DevTools Network tab or backend logs). Verify that the `dependencies` arrays correctly map the upstream-to-downstream flow and that the backend returns a mathematically valid topological execution order (e.g., Step 2 cannot execute before Step 1).
* **Contract Integrity Verification:** Verify the backend's strict adherence to Pydantic contracts. Intercept the `Project` creation response and assert that all fields rigidly match the `neurohub.contracts.Project` schema (e.g., enums for hardware targets strictly evaluate to permitted strings, metadata dictionaries are properly typed).
* **Asset Hashing Verification:** Manually compute the SHA-256 hash of the `.nir` file you uploaded using a terminal tool (e.g., `sha256sum model.nir`). Compare this manual hash against the hash displayed in the NeuroHub UI/Database. They must match exactly, proving the integrity layer is functioning.

### Module-Specific Edge Cases & Boundary Testing

Test these specific domain boundary conditions to ensure NeuroHub's validation logic behaves securely and predictably:

1. **Workflow DAG Circular Dependencies:**
   * *Test:* Attempt to create a workflow loop (e.g., connect Step C back to Step A as a dependency).
   * *Validation:* The internal `WorkflowTemplate` contract validation must immediately intercept this. The UI should block the action and display an explicit "Cycle Detected in DAG" error, as neuromorphic compilation pipelines must be strictly acyclic.

2. **Inconsistent Milestone-Project State Transitions:**
   * *Test:* Attempt to force the overarching `Project` status to "Completed" while one or more child `Milestones` are still flagged as "Pending" or "In Progress".
   * *Validation:* The domain invariant state machine should reject this transition. NeuroHub's contracts require all sub-milestones to be completed before the parent project can be marked closed.

3. **Isolated Workflow Steps:**
   * *Test:* Add a new workflow node to an existing multi-step pipeline but do not connect it to any incoming or outgoing edges.
   * *Validation:* The backend `WorkflowTemplate` contract should flag an "Isolated Step" violation. In a neuromorphic orchestrator, a step that neither consumes inputs nor produces outputs is an invalid pipeline state.

4. **Invalid SNN Asset Types:**
   * *Test:* Attempt to register a standard PyTorch (`.pt`) or raw text file, but maliciously bypass the UI to tag its metadata type as a compiled `nir` model.
   * *Validation:* The `SharedAsset` backend validation logic (or `nir_service.py` ingestion) should inspect the file signature/structure, identify the mismatch, and reject the registration to prevent downstream suite failures.

### Inter-Module Handoff Preparation

NeuroHub's primary job is to prepare data for the rest of the NMTK suite (e.g., sending a model to `neurosim` or `neurochip`). Verify the handoff mechanics as follows:

* **ExportBundle Structure:** When triggering a "Send to Module" action, intercept the `ExportBundle` payload. Verify that it contains a non-empty `contents` list, a valid `bundle_hash` for the entire package, and explicitly declares the target application (e.g., `"target": "neurosim"`).
* **Cross-Module Routing Alignment:** Check the `SuiteOrchestration` configuration block in the payload. Verify that the routing ports align with NMTK standards (e.g., checking it addresses the correct suite port) and that it passes the required contextual IDs (`project_id`, `workflow_id`).
* **Path Standardization:** Verify that any shared `nir` assets referenced in the handoff payload use standard, resolvable relative URIs mapped to the shared `nmtk_workspace/models/` directory, ensuring the receiving module can mount and access the SNN structure seamlessly.
