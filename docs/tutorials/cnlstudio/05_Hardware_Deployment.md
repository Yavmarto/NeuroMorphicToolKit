# 05: Hardware Deployment

The ultimate goal of the Neuromorphic Toolkit is to deploy models to low-power physical hardware. CNLStudio abstracts the complexity of compilation, quantization, and deployment into dedicated Hardware Panels.

## Hardware Targets and Server Setup

Before deploying, the system must know *where* to deploy.

1. **Server Setup Screen:**
   - Use this to configure connections to the main NMTK Backend.
   - Requires an IP Address (URLs/ports are handled automatically).
2. **Target Registry:**
   - CNLStudio maintains a registry of known hardware targets. You can add targets like specific PYNQ boards (via IP and SSH credentials) or Akida host servers.

## Export Menu and Quantization

If you simply want the compiled artifact without deploying immediately, use the **Export Menu**.

- **Formats:** You can export the raw CNL, the compiled NIR graph, or hardware-specific binaries.
- **Quantization:** Physical chips often require lower precision (e.g., 4-bit or 8-bit integers) than the 32-bit floats used in simulation.
- **Quantization Curve Chart:** When preparing an export, this chart shows the degradation in performance as precision drops. You must balance accuracy against the hardware constraints.

## Dedicated Deployment Panels

CNLStudio provides specialized UI panels for specific hardware backends.

### Teensy Deploy Panel
- **Target:** Teensy microcontrollers.
- **Mechanism:** Selects a serial port (`/dev/ttyACM0` or `COM3`).
- **Flow:** Flashes the compiled network directly via serial connection.

### PYNQ Deploy Panel
- **Target:** AMD Xilinx PYNQ FPGAs (e.g., PYNQ-Z2).
- **Mechanism:** Selects a configured board from the Registry.
- **Flow:** Synthesizes the network into a bitstream/overlay and pushes it via SSH to the board.

### Akida Deploy Panel
- **Target:** BrainChip Akida Neural Processors.
- **Mechanism:** Selects an Akida Host from the Registry.
- **Flow:** Maps the NIR graph to Akida hardware blocks, quantizes weights via the MetaTF pipeline, and deploys.

## Execution Flow for Humans & Agents

1. Open the specific Deploy Panel for your target (e.g., `PYNQ Deploy`).
2. Select the target device from the dropdown.
3. Validate the model for that specific hardware (e.g., check that the architecture is supported by the specific FPGA overlay).
4. Click `Deploy`.
5. Monitor the shell output view (often hosted in a `ShellSurface` widget) for build logs and compilation errors.

- **Agent Note:** Deployment operations are asynchronous and can take several minutes (especially FPGA bitstream synthesis). Agents should monitor the respective `DeployProvider` state for `success` or `error` flags, and read the structured error objects generated by `DeployErrorFormatter` if a failure occurs.
