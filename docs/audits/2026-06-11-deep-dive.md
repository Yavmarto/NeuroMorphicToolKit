# NeuroMorphicToolKit Deep-Dive Audit — 2026-06-11

**Scope:** Full monorepo, 10 modules, all 1,269 source files indexed.
**Lens:** End-user convenience first (per `AGENTS.md`), architecture second.
**Weighting:** User-convenience 2× architectural risk.
**Mode:** Read-only audit. No code edits performed.

---

## Scoring rubric (applied to every finding)

- **U1 — Error message quality** (actionable, no raw stack traces to user)
- **U2 — Default-config auto-detection** (zero user-typed URLs/ports)
- **U3 — First-run friction** (clicks/steps from `git clone` to working app)
- **U4 — Silent degradation** (failure presented as "fine")
- **A1 — Blast radius** (how many modules break)
- **A2 — Churn × complexity** (bug-prone-ness)

Each axis 0–5. Composite: `U = max(U1..U4)`, `A = max(A1, A2)`, **score = 2U + A**.

## Top 5 user-visible wins (do these first)

### 1. `process_manager.dart` — raw `Exception` strings surface to end users
**Files:** `nmtk/neuro_toolkit/lib/services/process_manager.dart:473,525,556,607,697,836,881,1268`
**Hits:** 8 `throw Exception(...)` sites with no user-facing translation layer.
**Axes:** U1 = **5** · U4 = **4** · A2 = **5** (CCN 127, 51 churns in 90d) · **Score = 15**

End user sees e.g. `Exception: Failed to create venv: <raw stderr>` instead of "Python 3.11 isn't installed. Install it from python.org and click Retry." This violates AGENTS.md "Error messages must be actionable" rule directly. **Fix:** add a `LauncherError` class with `userMessage` and `recoveryAction` fields, and a top-level handler in `nmtk_ui_core` that renders the recovery action.

### 2. `process_manager.dart` — placeholder/stub returns (15 sites)
**Files:** `nmtk/neuro_toolkit/lib/services/process_manager.dart:268,399,411,422,442,454,458,1001,1007,1011,1050,1079,1098`, `nmtk/neuro_toolkit/lib/main.dart:26,163`
**Hits:** 15 `return null/false/0/true` default branches in functions that are part of the module-startup critical path.
**Axes:** U4 = **5** · U3 = **4** · A2 = **5** · **Score = 15**

When a module fails to bootstrap (no port, no venv, no Akida runtime), the function returns a "looks-fine" default. The user clicks Start, sees the spinner, the spinner stops, **nothing happens**, no error. The most painful failure mode in the product. **Fix:** every default-return in the startup path must either throw `LauncherError` or post a non-closable toast.

### 3. `process_manager.dart` — 1,311 lines, CCN 127
**File:** `nmtk/neuro_toolkit/lib/services/process_manager.dart`
**Axes:** A2 = **5** · U3 = **3** (every bug here lands in the user's face) · **Score = 11**

This file owns venv creation, pip bootstrap, port allocation, process spawning, health checks, Akida runtime discovery, and bundle management. Six distinct concerns. A 1,311-line class is why placeholder returns are everywhere — the per-concern path is hard to follow. **Fix:** split into `VenvProvisioner`, `ProcessSupervisor`, `AkidaRuntime` (user-visible behavior is unchanged; internal cohesion is fixed). Acceptable to ship as a pure refactor behind the same public API.

### 4. `tool_view.dart` — 741 lines, churn 42, CCN 124
**File:** `nmtk/neuro_toolkit/lib/screens/tool_view.dart`
**Axes:** A2 = **5** · U3 = **3** · **Score = 11**

The screen that shows running modules. 42 commits in 90 days means the UI keeps moving under the user — every churn cycle risks a regression in the screen they see most. **Fix:** add a widget-test that asserts the module-card renders state from `ProcessState` (a contract test), so the churn stops breaking the user-visible surface.

### 5. `nmtk_ui_core/lib/shell_tokens.dart` + `app_theme.dart` — design system not enforced
**Files:** `nmtk_ui_core/lib/shell_tokens.dart` (CCN 133, churn 8), `nmtk_ui_core/lib/app_theme.dart` (CCN 93, churn 21)
**Axes:** U2 = **4** (every screen is a custom layout = no consistent "where do I click") · A2 = **4** · **Score = 12**

`shell_tokens.dart` and `app_theme.dart` are the design system, but `nmtk_ui_core/lib/neat/dark/cut/` contains ~20 hand-rolled cards that don't import them. The user sees inconsistent padding, colors, and typography across screens. **Fix:** add a lint rule (`flutter_lints` custom rule or `dart analyze` check) that fails if a widget in `nmtk_ui_core/lib/neat/dark/cut/` uses `Color(0x...)` or `EdgeInsets.all(N)` directly.

## Top 5 architectural risks with user impact (deferred)

### A. `nmtk/neuro_toolkit/assets/modules.json` — zero test coverage
**File:** `nmtk/neuro_toolkit/assets/modules.json`
**Axes:** A1 = **4** (8 modules depend on it) · U3 = **3** (the launcher fails on a malformed entry, user sees crash) · **Score = 11**

`test_impact` confirms: no tests cover this file. `nmtk/neuro_toolkit/test/launcher_e2e_test.dart` churns 40× in 90d — likely because every modules.json change breaks the e2e. **Fix:** add a `test/modules_manifest_test.dart` that validates required keys, port ranges, and run-path existence. Once the manifest is contract-tested, the e2e churn will drop.

### B. `scripts/launcher_control_service.py` — 18-line shim with no error handling
**File:** `scripts/launcher_control_service.py`
**Axes:** A1 = **3** (called by launcher doctor) · U1 = **3** · **Score = 9**

If the import fails (missing dependency, wrong Python), the user sees a raw `ModuleNotFoundError` or `ImportError` traceback. The shim is correct — it just doesn't catch and translate. **Fix:** wrap the import in a try/except that prints a one-line message: "Launcher requires Python ≥3.11. Run: pip install -e nmtk/launcher_control".

### C. `models/module.dart` — 701 lines, CCN 409
**File:** `nmtk/neuro_toolkit/lib/models/module.dart`
**Axes:** A2 = **5** (the model is touched by every UI screen) · U3 = **2** · **Score = 12**

A 409-cyclomatic-complexity model is a future bug factory. Every new module field propagates here. **Fix:** extract `ModulePort`, `ModuleRuntime`, `ModuleBundle` as value types; the `Module` aggregate becomes a thin composition.

### D. `pynq_deployment_model.dart` and `akida_deployment_model.dart` — 325 and 369 CCN
**Files:** `nmtk_ui_core/lib/models/pynq_deployment_model.dart`, `nmtk_ui_core/lib/models/akida_deployment_model.dart`
**Axes:** A2 = **4** · U3 = **3** (these power the deployment UI) · **Score = 11**

Combined 694 CCN for two model classes that are doing UI serialization + business logic + validation. **Fix:** see the Pydantic v2 pattern already in `Neurochip/neurochip/contracts/` — use the Python contracts as the single source of truth and generate the Dart models.

### E. `bundle_manager.dart` — churn 31, no public docs
**File:** `nmtk/neuro_toolkit/lib/services/bundle_manager.dart`
**Axes:** A2 = **4** · U2 = **3** (bundles are the auto-detect path; user can't see why a bundle is missing) · **Score = 11**

When a bundle is missing, the user gets "Module not found" or similar opaque text. **Fix:** add a public method `explainBundleStatus(moduleId) -> String` that the UI can render.

## Tooling gaps surfaced by this audit

1. **`co_change_analyzer` does not filter deleted paths** — flagged in this audit; needs a `--since <date>` or `--alive-only` flag.
2. **`secretscan` scans `.test-venv/`** — generates ~80 noise findings per scan. Add `.test-venv/` to default exclusions or honor a `.secretscanignore` more aggressively.
3. **`sast_scan` returned 0 files scanned** at the repo root — likely needs a more specific path or an extension allowlist. Investigate before relying on it.
4. **`repo_map` blast_radius returns 0 for static assets and entry-point scripts** — these don't have import relationships, but the user-visible risk is real. Add a "static-asset" awareness to the blast-radius scorer.
5. **`knowledge_recall` returns stale deleted-path entries** — see #12 in the backlog.
