Workflow Stepper: Current vs Proposed

Does the proposed 7-step flow better match what each canvas actually does?

Current — 5 steps
1
Setup
Dataset · Platform · Workspace
2
Architecture
CNL · Topology · NIR
3
Notebook
⚠ Before training config
4
Train & Export
⚠ Config + Eval + Run merged
5
Deploy
Hardware · Target · Compile
Problems:
· Notebook sits before training pipeline is even configured — cart before horse
· "Train & Export" bundles 3 distinct things: train DAG config, eval DAG config, and actually running
· No explicit Eval step, even though pipelineEval canvas already exists
· Step labels don't match canvas tab names users actually see
Proposed — 7 steps
1
Setup
unchanged
2
Model
architecture canvas
3
Training
pipelineTrain DAG
4
Eval
pipelineEval DAG
5
Notebook
Jupyter · explore
6
Run
execute · monitor
7
Deploy
unchanged
Wins:
· Each step = one canvas tab — 1:1 mapping, no confusion
· Eval gets its own step (canvas already built!)
· Notebook after config = makes sense: explore once model + pipelines are defined
· Run separated from config: "set it up" vs "execute" are different mental modes
One open question
Where does pipelineInfer (the Infer DAG canvas) live?
Currently it's a canvas tab with export nodes (NIRExporter, TorchScript, Loihi). Two options:
· Fold into Deploy (configure inference pipeline before hardware deploy)
· Add as step 7.5 Infer between Run and Deploy (explicit inference pipeline config)

Notebook step also has a question: is it optional (exploratory, skip if not needed)?
