# Consolidate to one working "connect to server" screen

## Problem
The app showed two different "connect to server" screens: the launcher's own screen (`nmtk/neuro_toolkit/lib/screens/server_setup.dart`, no icon) which configures the launcher's control-API host and gates cold start, and the neurocnl module's screen (`neurocnl/frontend/lib/screens/server_setup_screen.dart`, `Icons.dns_rounded` header icon) which force-redirected to itself every time the neurocnl/Neurochip module was opened, even after the launcher was already connected. The launcher's screen looked broken: it received a `message` prop with the real connect success/failure text but never rendered it, had no `try/catch` around the connect callback, and `main.dart` captured the typed host in a local variable that got silently reset on rebuild.

## Fix
- `nmtk/neuro_toolkit/lib/screens/server_setup.dart`: render `widget.message`/a new `_connectError` state (styled like the existing Python-install error text in the same screen family), added a `Icons.dns_rounded` header icon, changed `onConnect` to `Future<void> Function(String host)?` so it reads `_controller.text` directly instead of relying on an external mutable variable, dropped the now-unneeded `onChanged` param.
- `nmtk/neuro_toolkit/lib/screens/first_run_setup_screen.dart` and `lib/main.dart`: updated to the new `onLauncherConnect(host)` signature; deleted the `var typedHost` closure-capture bug.
- `nmtk/neuro_toolkit/lib/src/features/launcher_bootstrap/presentation/launcher_bootstrap_notifier.dart`: the settings-load failure message interpolated a raw exception (`... : $error`) directly into user-facing text — now that the message is actually rendered, replaced it with actionable, non-raw-exception copy.
- `nmtk/neuro_toolkit/lib/screens/backend_setup.dart`: deleted the dead `@Deprecated class BackendSetupScreen` (zero references anywhere).
- Deleted `neurocnl/frontend/lib/screens/server_setup_screen.dart`, its `/setup` route and forced redirect in `routing/app_router.dart`, and `sessionVerified`/`markSessionVerified()` from `services/server_config_service.dart` (kept `serverUrl`/`saveUrl`/`isConfigured` — still used by the API client).
- Deleted `neurocnl/frontend/lib/services/backend_issue_formatter.dart` and its test — confirmed fully orphaned (only caller was the deleted screen).
- Threaded the launcher's already-known backend host into the embedded module instead of asking twice: `tool_view.dart` computes `_nativeSurfaceServerUrl(module)` (same host/scheme resolution as the existing webview path, `/api/neurocnl` path, only for modules on the monolith port 9000) and passes it through `native_surface_registry.dart` → `NeurocnlShellAdapter` (`shell_adapter.dart`) → `NeurocnlStudioApp` (`app.dart`), which calls `ServerConfigService.saveUrl()` during bootstrap when a host is supplied. Standalone/no-host case still falls back to `AppConfig.setupDefaultUrl`.
- Updated tests: removed now-pointless `ServerConfigService.markSessionVerified()` calls in `widget_test.dart`, `preservation_property_test.dart`, `pipeline_integration_test.dart`; deleted `test/screens/server_setup_screen_test.dart` and `test/services/backend_issue_formatter_test.dart`.
